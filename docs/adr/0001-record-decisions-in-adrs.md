# Record decisions in ADRs and grill designs with `grill-with-docs`

We record important decisions about Balmorel as short Architecture Decision Records (ADRs) in `docs/adr/` (`0001-slug.md`, `0002-slug.md`, ...). We keep shared terminology in a `GLOSSARY.md` at the repository root. This follows the conventions of Matt Pocock's [domain-modeling](https://www.skills.sh/mattpocock/skills/domain-modeling) skill, so the reasoning behind a choice stays next to the code instead of in someone's memory. Write an ADR only when a decision is hard to reverse, would surprise a future reader, and came from a real trade-off. One paragraph is usually enough.

When developing Balmorel, for example adding an addon or changing equations or data structures, we recommend running the [grill-with-docs](https://www.skills.sh/mattpocock/skills/grill-with-docs) skill with your coding agent. It questions you about the plan until the design is clear, and it uses domain-modeling to write ADRs and glossary entries as decisions are made. To install it, run `claude plugin install mattpocock-skills@claude-plugins-official` for Claude Code, or `npx skills@latest add mattpocock/skills` for other agents.
